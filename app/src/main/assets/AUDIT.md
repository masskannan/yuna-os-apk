# YUNA UI r5 — Production-readiness தணிக்கை (22 நவ 2026)
backend இணைக்கவில்லை என்ற அனுமானத்தில், UI மட்டும். சோதனை: Chromium 360×640 (உண்மையான APK/சாதனத்தில் அல்ல).

## 0. நேர்மையான மதிப்பெண்
**இப்போது ≈ 70/100.** வடிவம், தொடு இலக்கு, இருமொழி, பிழையின்றி ஓடுதல் நன்றாக உள்ளன. ஆனால் "100/100" ஆவதற்கு: (அ) APK-ல் மட்டும் சரிபார்க்கக்கூடிய 12 விஷயங்கள், (ஆ) UI-ல் இன்னும் இல்லாத அம்சங்கள் (streaming, edit, Home orb/quick rail, first-run), (இ) உங்கள் 4 முடிவுகள் தேவை. கீழே முழுப் பட்டியல்.

## 2. தானியங்கிச் சோதனை — என்ன ஓடியது
- **360 நிலைகள்**: 12 சூழல் (320×568, 360×640, 412×915 × தமிழ்/English × ஒளி/இருள்) × 30 திரை/நிலை (முகப்பு, drawer, மெனு, இணைப்புத் தாள், வரலாறு, chat, தேடல், Live, Live-தட்டச்சு, dialog, 19 Pg பக்கங்கள்).
- ஒவ்வொரு நிலையிலும்: தொடு இலக்கு <48px, பொத்தான்-பொத்தான் மேல்படிதல், மேலே வேறொன்று மறைத்தல் (elementFromPoint), கிடைமட்ட scroll/திரைக்கு வெளியே, JS பிழை.
- **முடிவு (r5):** உண்மையான மீறல் 0. மீதமுள்ள 7 வரிகள் "மெனு தட்டு Home chips மேல் மிதக்கிறது" — இது வடிவமைப்பு, பிழை அல்ல.
- "ஒரு பொத்தானைத் தொட்டால் இன்னொன்று தொடப்படுகிறது" வகை: மேல்படிதல் + மறைப்பு இரண்டும் 0. **ஆனால்** விசைப்பலகை திறந்த நிலை, நிஜத் தொடு (விரல் அளவு), 200% எழுத்துரு — இவை Chromium-ல் முழுமையாக உருவகிக்க முடியாது → APK-ல் §5.
- நடத்தை script: 🔊, 👍👎, Pin/மறுபெயர், தேடல், Back, மொழி மாற்றம், அனுமதி வழங்கல், chat-மாற்றம் நடு-கோரிக்கை — அனைத்தும் தேர்ச்சி.
- **நான் செய்யாதது:** உண்மையான 200–300 *நடத்தை* சூழ்நிலைகளை ஓட்டவில்லை; அவை §7 பட்டியலில் (✓ / ✗ / APK) நிலையுடன்.

## 4. நுழைவு (entry) தர்க்கம்
1. app திறக்கும் → நேரத்துக்கேற்ற வாழ்த்து + 4 starter chips. ✅
2. மைக்/Accessibility OFF → மேலே சிவப்புக் கோடிட்ட பட்டை "n அனுமதி தேவை · அமை". ✅
3. 🎙 தட்டும்போது மைக் OFF → toast + "இயக்கு". ✅
4. Android அமைப்பிலிருந்து திரும்பு → திரை + பட்டை தானாகப் புதுப்பிப்பு. ✅
5. **இல்லாதது:** முதல்-முறை அறிமுகம் (B10), உரிமையாளர் குரல்/கைரேகை சரிபார்ப்பு தொடக்கத்தில், ஒவ்வொரு அம்சத்துக்கும் தனி "permission gate" (B9). இவற்றுக்கு "பார்த்துவிட்டேன்" நிலையைச் சேமிக்க புதிய key தேவை → உங்கள் ஒப்புதல் (§6).

## 5. APK-ல் மட்டும் சரிபார்க்க (என்னால் முடியாதவை)
1. `<a download>` சேமிக்கிறதா (இல்லையெனில் Kotlin DownloadListener — உங்கள் விதி மீறல்).
2. கோப்பு/கேமரா chooser (`<input capture>`) WebView-ல் திறக்கிறதா; CAMERA runtime கேட்கிறதா.
3. `openPermissionSettings(key)` ஒவ்வொரு key-க்கும் சரியான Android பக்கம் திறக்கிறதா (mic → runtime dialog?).
4. `onYunaAppResumed` உண்மையில் அழைக்கப்படுகிறதா.
5. `onYunaTtsDone` வருகிறதா (🔊 பொத்தான் ■-லிருந்து திரும்ப).
6. விசைப்பலகை: `adjustResize` + `--kb`; தமிழ் IME; 8 வரி; split-screen.
7. Back: Live சிறிதாக்கப்பட்டபோது (mini pill) Back — இப்போது app வெளியேறும்; முடிவு தேவை.
8. மிதக்கும் பந்தை OFF செய்தால் நிறுத்த bridge அழைப்பு இல்லை (37-ல் `stopFloatingOverlay` இல்லை) → switch OFF ஆனாலும் ball இருக்கும்.
9. Android 13+ POST_NOTIFICATIONS, BLUETOOTH_CONNECT runtime கோரிக்கைகள்.
10. எழுத்துரு 200%, TalkBack, குறைந்த பேட்டரி, இருள்/ஒளி மாற்றம் நடுவில்.
11. 60 chat + பெரிய `yuna_sessions` JSON (localStorage ~5MB) வேகம்.
12. Notch/gesture-bar உள்ள சாதனங்களில் dock-ன் கீழ் இடைவெளி.

## 6. உங்கள் முடிவு தேவை
1. **புதிய localStorage key** (`yuna_v4_state`, `yuna_float_on`, இனி `yuna_seen_intro` தேவைப்படலாம்) — ஒப்புதல்?

**P1 — அனுபவம்**

## 8. தமிழ் / English தணிக்கை
- 194 இருமொழி ஜோடிகள்: English-ல் தமிழ் கலந்தது **0**; ஒரே மாதிரி (Code) 1 — சரி.
- **கிரந்த எழுத்துகள்:** 2 இடங்கள் மட்டும்: `ஸ்கேன்` (scan) மற்றும் GPay-க்கான `ஜிபே` (பெயர் பொருத்தம், பயனருக்குத் தெரியாது). `ஸ்கேன்` நடைமுறையில் எல்லோரும் அறிந்தது → "ஸ்கேன் செய்" என்றே வைக்கலாம்; தூய தமிழ் வேண்டுமெனில் "வருடு".
